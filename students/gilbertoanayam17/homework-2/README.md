**Student**: Gilberto Anaya Mercado
**Application**: Trello
**Date**: 2026-09-07

## Summary

This submission designs a test strategy for **Trello**, a kanban tool where teams organise work into boards, lists and cards. The strategy follows from what makes Trello different: every change is pushed in real time to everyone else viewing the board, so concurrency, sync and permission enforcement carry more risk than any single feature. Nine testing types, the four testing levels and the seven principles are applied to that context, and a risk matrix sets the final priority order.
