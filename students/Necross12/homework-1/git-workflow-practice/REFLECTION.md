# Reflexión
La verdad, nunca había hecho nada similar, por lo cual terminé usando más de lo que me gustaría admitir `git reset --soft HEAD~1` para poder dar un paso atrás y volver a hacer el commit, ya fuera por el nombre del commit en sí o por agregar un archivo de más. A la par, usé mucho `git add` especificando un archivo, ya que estoy acostumbrado a hacerlo de manera global (*). Lo que más me gustó para los trabajos en equipo fueron las versiones (tags), ya que no sabía de su existencia y me resultan sumamente útiles para trabajar con las demás personas y saber de manera fácil qué es lo que funciona. A la par, usar el PR para documentar los cambios de manera rápida se me hace algo muy sencillo y que puede ayudar mucho a los proyectos al momento de revisar código. En cuanto a la estrategia, traté de practicar siguiendo todo lo visto en la lectura para seguir mejorando, con comentarios bien hechos, acciones ordenadas y ramas claras para la mejor lectura posible. En sí, el plan fue fácil, ya que me inspiré en las lecturas: una rama para iniciar (más que nada por costumbre con otros proyectos) y otras para darle contenido a esos archivos (una para estilo, otra para el contenido de Handlebars y otra para documentación).
