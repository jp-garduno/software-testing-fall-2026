# Git Workflow Reflection

## Challenges

One of the main challenges I faced was understanding how branches work and why changes should be developed separately instead of directly on the main branch. At first, I was confused about when to create a branch, when to switch branches, and how pull requests were connected to the workflow. After practicing the process several times, I became more comfortable with it.

Another challenge was making small and meaningful commits instead of putting all the changes into one commit. Creating separate commits helped me understand how Git keeps track of the development history.

## Useful Git Commands

The commands I found most useful were `git status`, `git checkout`, `git add`, `git commit`, `git push`, and `git pull`.I used `git status` frequently to check the current branch and see which files had changed. `git checkout -b` was useful for creating new feature branches, while `git push` allowed me to upload my branches to GitHub and create pull requests.

## Branching Strategy

I created three feature branches:

- `feature/initial-structure`
- `feature/add-styling`
- `feature/add-content`

Each branch focused on a different part of the portfolio website and was merged into `main` through a pull request.

## Applying This Workflow

I will use this workflow in the team project by creating separate branches for different features or fixes, making clear commits, and using pull requests before merging changes into the main branch. This should make collaboration easier and help keep the project organized.
