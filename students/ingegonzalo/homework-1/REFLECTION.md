# Reflection

During this assignment I practiced using Git through a complete feature branch workflow instead of making all changes directly on the main branch, as well as sticking to a cleaner format when working with Git. One challenge was understanding some particular Git Bash Commands, i had to go back to previous exercises to double check syntaxis.

The Git commands I found most useful were git log --oneline, git branch -a, git add, git commit, and the git checkout variants.

My branching strategy was based on creating independent feature branches from main to feature/initial-structure, back to main, then to feature/add-styling, and so on with feature/add-content. After completing each feature, I created a pull request, documented the changes, and merged it back into the main. This approach kept my project organized and simplified the Pull Request process for my understanding, i've done them in the past but always with conflicts.

In future team projects I will use this workflow to keep features isolated, review changes through pull requests, and maintain a cleaner project history. Nevertheless from theory to practice when involving more colaborators could prove itself to be more difficult.
