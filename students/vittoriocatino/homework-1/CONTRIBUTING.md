# Contributing

1. Start from an up-to-date `main` branch.
2. Create a descriptive branch such as `feature/improve-project-cards`.
3. Keep each commit focused and use a conventional commit message.
4. Review `git diff` and test the portfolio in a browser before opening a pull request.
5. In the pull request, describe the change, its motivation, and how it was checked.

This lightweight workflow keeps review straightforward and preserves a useful project history.
