# Testing Concepts Quiz

**Module**: 2 - Software Testing Concepts  
**Time**: 20-30 minutes  
**Questions**: 20

---

## Instructions

Answer the following questions to test your understanding of software testing concepts. Answers are at the bottom.

---

## Questions

### Introduction to Testing

**1. What is the primary goal of software testing?**
- A) To prove software has no bugs
- B) To find defects and verify requirements
- C) To replace good development practices
- D) To delay project delivery

**2. Which statement about testing and debugging is TRUE?**
- A) Testing and debugging are the same thing
- B) Testing finds bugs, debugging fixes them
- C) Debugging is more important than testing
- D) Testing should only be done after debugging

**3. According to the "Rule of 10", fixing a bug in production costs approximately how much more than fixing it during requirements?**
- A) 2x more
- B) 10x more
- C) 100x more
- D) 10,000x more

### Testing Types

**4. Which is an example of functional testing?**
- A) Testing page load speed
- B) Testing if login works with correct credentials
- C) Testing if system handles 1000 users
- D) Testing if UI is user-friendly

**5. Which is an example of non-functional testing?**
- A) Testing add-to-cart functionality
- B) Testing search feature
- C) Testing website performance under load
- D) Testing form validation

**6. What is the difference between smoke testing and sanity testing?**
- A) They are the same thing
- B) Smoke is broad/shallow, sanity is narrow/deeper
- C) Smoke is for bugs, sanity is for features
- D) Smoke is manual, sanity is automated

**7. What is regression testing?**
- A) Testing new features only
- B) Testing that existing features still work after changes
- C) Testing for performance degradation
- D) Testing backwards compatibility

### Testing Levels

**8. In the testing pyramid, which should have the MOST tests?**
- A) UI/End-to-end tests
- B) Integration tests
- C) Unit tests
- D) Acceptance tests

**9. Which testing level tests individual functions/methods in isolation?**
- A) Unit testing
- B) Integration testing
- C) System testing
- D) Acceptance testing

**10. Who typically performs User Acceptance Testing (UAT)?**
- A) Developers
- B) QA team
- C) End users or business stakeholders
- D) DevOps engineers

**11. Which testing level verifies that components work together correctly?**
- A) Unit testing
- B) Integration testing
- C) System testing
- D) Acceptance testing

### Testing Principles

**12. "Testing shows presence of defects" means:**
- A) Testing proves there are no bugs
- B) Testing can show bugs exist, but cannot prove they don't exist
- C) All bugs will be found by testing
- D) Testing always finds defects

**13. Why is exhaustive testing impossible?**
- A) Not enough time
- B) Not enough testers
- C) The number of possible test cases is too large
- D) Management doesn't allow it

**14. What does "early testing" mean?**
- A) Testing in the morning
- B) Testing before coffee
- C) Starting testing activities as early as possible in SDLC
- D) Testing the first feature developed

**15. What is "defect clustering"?**
- A) All bugs are found together
- B) A small number of modules contain most defects
- C) Bugs group by type
- D) Testers work in clusters

**16. What is the "pesticide paradox"?**
- A) Tests kill bugs like pesticides
- B) The same tests repeatedly won't find new bugs
- C) Too much testing is harmful
- D) Bugs develop resistance to testing

**17. "Testing is context dependent" means:**
- A) All projects test the same way
- B) Context doesn't matter in testing
- C) Different projects need different testing approaches
- D) Testing depends on the weather

**18. What is the "absence of errors fallacy"?**
- A) No bugs means good software
- B) Bug-free software is useless if it doesn't meet user needs
- C) Errors are always absent
- D) Testing should find all errors

### Application

**19. For a medical device software, what should be the PRIMARY testing focus?**
- A) Fun and aesthetics
- B) Reliability, safety, and compliance
- C) Low cost
- D) Fast development

**20. Which testing approach would be BEST for a critical banking transaction system?**
- A) Only manual testing
- B) Only automated testing
- C) No testing (trust the developers)
- D) Comprehensive testing at all levels with focus on security

---

## Answers

1. **B** - To find defects and verify requirements
2. **B** - Testing finds bugs, debugging fixes them
3. **D** - 10,000x more (exponential increase)
4. **B** - Testing if login works (tests functionality)
5. **C** - Performance testing (tests quality attribute)
6. **B** - Smoke is broad/shallow, sanity is narrow/deeper
7. **B** - Testing that existing features still work
8. **C** - Unit tests (most tests at the bottom of pyramid)
9. **A** - Unit testing
10. **C** - End users or business stakeholders
11. **B** - Integration testing
12. **B** - Can show bugs exist, cannot prove they don't
13. **C** - Too many possible test cases
14. **C** - Starting testing early in SDLC
15. **B** - Small number of modules contain most defects
16. **B** - Same tests won't find new bugs
17. **C** - Different projects need different approaches
18. **B** - Bug-free doesn't mean it meets user needs
19. **B** - Reliability, safety, and compliance
20. **D** - Comprehensive testing with security focus
