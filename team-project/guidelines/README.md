## 💡 Key Principles

### Code Quality

- Write clean, readable code
- Follow consistent style
- Document complex logic
- Test before committing

### Collaboration

- Communicate early and often
- Review each other's code
- Share knowledge
- Help teammates

### Testing

- Test-first when possible
- Aim for high coverage
- Test edge cases
- Keep tests maintainable

### Process

- Commit regularly
- Use conventional commits
- Create small PRs
- Respond to reviews promptly

## 🚀 Success Factors

Based on past successful teams:

1. **Start early** - Don't wait for deadlines
2. **Meet regularly** - Weekly syncs minimum
3. **Communicate clearly** - Use GitHub Issues, Slack, etc.
4. **Review code** - Learn from each other
5. **Test continuously** - Don't leave testing to the end
6. **Document as you go** - Don't wait until M7
7. **Ask for help** - Use office hours

## ⚠️ Common Pitfalls

Avoid these mistakes:

- Waiting too long to start
- One person doing all the work
- Not testing until the end
- Poor communication
- Ignoring code review feedback
- Scope creep (adding too many features)
- Not using version control properly

## 📞 Getting Help

- **Office Hours**: Weekly availability
- **GitHub Discussions**: Ask questions
- **Team Consultation**: Schedule with instructor
- **Peer Learning**: Learn from other teams
