- Document all major decisions in meeting notes

## 🚫 Conflict Resolution

### How We Handle Disagreements

1. **Discuss openly**: Talk it out during meeting
2. **Listen actively**: Each person gets to explain their view
3. **Focus on project**: What's best for the project, not ego
4. **Compromise**: Find middle ground
5. **Escalate if needed**: Ask instructor for guidance

### If Someone Isn't Contributing

1. **Week 1**: Friendly reminder in team chat
2. **Week 2**: Private conversation with team member
3. **Week 3**: Team meeting to discuss concerns
4. **Week 4**: Inform instructor

### If Someone Misses Deadlines

- First time: Understanding - life happens
- Pattern emerges: Team discussion
- Continued: Adjust responsibilities or inform instructor

## 🔄 Git Workflow

### Branching

```
main (protected)
  ├── develop (integration)
  │   ├── feature/user-auth (Member 2)
  │   ├── feature/product-catalog (Member 3)
  │   └── fix/cart-bug (Member 4)
```

### Pull Request Process

1. **Create PR** from feature branch to `develop`
2. **Describe changes** - what and why
3. **Request review** from at least 1 teammate
4. **Address feedback** within 24 hours
5. **Merge** once approved and CI passes
6. **Delete** feature branch after merge

### Code Review Expectations

**As Author**:

- Keep PRs small (< 400 lines)
- Write clear PR description
- Respond to feedback politely
- Don't take criticism personally

**As Reviewer**:

- Review within 48 hours
- Be constructive, not critical
- Suggest improvements, don't demand
- Approve if no blocking issues
